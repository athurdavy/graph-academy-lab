# Evaluación rigurosa: credenciales externas y expediente verificable

## No confundir título con portafolio

La web puede proporcionar formación y artefactos verificables, pero **no puede emitir por sí sola una titulación oficial** universitaria o una certificación emitida por Neo4j, W3C, Stanford u Ontotext. El alumno debe realizar los exámenes de los organismos correspondientes.

## Rúbrica interna propuesta

| Componente | Peso |
|---|---:|
| Conceptos de Cypher, RDF, SPARQL y OWL | 20 % |
| Laboratorios con tests reproducibles | 25 % |
| Modelado, validación y calidad de datos | 15 % |
| Arquitectura, rendimiento y operación | 15 % |
| Proyecto y defensa técnica | 25 % |

**Umbrales internos orientativos:** 80/100 general, 70/100 por bloque, sin incumplimientos críticos de seguridad y defensa satisfactoria. No son criterios de acreditación externa.

## Evidencias que debe guardar el estudiante

- Commits y entregables reproducibles.
- Versiones de programas y dependencias.
- Dataset 100 % ficticio, licencias y procedencia.
- Consultas Cypher, SPARQL y RDF exportado con resultados esperados.
- Ontología OWL y comprobaciones en Protégé.
- Repositorio GraphDB con consultas e inferencias explicadas.
- Shapes SHACL con ejemplos válidos e inválidos.
- API Python, tests, pruebas de integración y decisiones de arquitectura.
- Memoria final y defensa técnica.
